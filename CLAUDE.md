# Modern GL

Бухгалтерская программа (главная книга) в стиле 1С 7.7: проводки Дт/Кт с субконто, несколько компаний, параллельные книги (общая / МСФО / налог). Пользователь общается по-русски.

Начало сессии: прочитать `docs/CONCEPT.md` (рамка — меняется только решением пользователя), `docs/STATUS.md` (что есть, что дальше), `docs/ENGINEERING.md`; `docs/ARCHITECTURE.md` — когда работа касается устройства; `docs/DESIGN.md` — когда касается вида (страницы, отчёты). `docs/DECISIONS.md` целиком не читать — искать решение по номеру (`| D72 |`) или слову; при расхождении решение важнее остальных документов. `docs/history/` — архив, читать только при надобности.
Конец сессии: запись — свой файл `docs/history/sessions/ГГГГ-ММ-ДД-<ветка>.md`, сделанное убрать из `docs/STATUS.md`, обновить «Долг» в `docs/ENGINEERING.md`, проверки `docs/CODE_QUALITY.md` (разделы 4 и 5 — код и документы: `tests/test_docs_size.py`); раз в ~5 сессий и перед слиянием большой ветки — полный обзор кода и документов по чек-листам оттуда же.

## Параллельные сессии (D131)
- **Сессия — в своём worktree и ветке** с первого шага (`git worktree add .claude/worktrees/<имя> -b claude/<имя> master`). Основная папка — только для слияния: там не работать, не оставлять незакоммиченного, чужое не трогать.
- **Номера — при слиянии:** решение в ветке — `D-new` (`D-new1`…), при слиянии — следующий номер `master` везде (`grep -rn "D-new"`); миграция занята — переименовать, поправить `FROZEN`; номер сессии не нужен.
- **Свои файлы, не общий конец:** запись сессии — `docs/history/sessions/`, переводы — `i18n_az/<функция>.py`; общие документы — короткие правки в конце.
- **Слияние по одной ветке:** `git merge master` → `uv run pytest -q -n auto` → `git merge --ff-only` в `master`; `master` ушёл вперёд — повторить.

## Команды
- Тесты: `uv run pytest -q -n auto` (параллельно, pytest-xdist; один файл — без `-n`)
- Линтер: `uv run ruff check . && uv run ruff format --check .`
- Типы: `uv run pyright` (тот же движок, что Pylance; должно быть 0 ошибок)
- Программа: `uv run modern-gl` — компании это файлы `*.gl` в «Документы\Modern GL» (`--data <папка>` — другая папка, запоминается); `--demo` добавляет демо-компанию в пустую папку; `--demo-year` — компанию с целым 2026 годом во всех модулях (`demo_year/`), `--demo-years` — та же компания за 2025 и 2026
- Скриншоты для проверки дизайна: `uv run python scripts/screenshots.py <папка>` — после любых изменений UI смотреть их
- Демо в консоли: `uv run python scripts/demo.py`
- Размеры кода (самые большие места): `uv run python tests/test_code_size.py`; документов — `uv run python tests/test_docs_size.py`
- Замеры на большой базе: `uv run python scripts/benchmark.py <папка> --postings 100000`
- Для разработчиков: `uv run modern-gl-cli chart|trial-balance|export|import <файл.gl> …` — JSON на выходе (`docs/API.md`, D130)
- AI-помощник (MCP): `uv run modern-gl-mcp` (только чтение; `--allow-drafts` — AI готовит черновики) — подключение в `docs/ASSISTANT.md`

## Структура
- `src/modern_gl/domain` — деньги, даты, ошибки. Без SQL и Qt. Переводы — пакет `src/modern_gl/i18n_az/` (`core` — до сессии 57, новое — свой файл).
- `src/modern_gl/application/ledger/` — все операции записи и правила учёта: `Ledger` собран из групп (`companies`, `currencies`, `subconto`, `chart` + `account_types`, `templates`, `documents`, `validation`, `document_import`, `revaluation`, `opening`, `subconto_details`, `account_form`); общее модулей — `module.py`; счёт по умолчанию — `default_accounts.py` (по роли/типу, не по коду).
- `src/modern_gl/application/` (общее): `books` — книги и `docs_cte` (D7); `invoices` + `invoice_rules` — проводки по номеру e-qaimə, неоплаченные (D120); `attention` — реестр «Требует внимания»; `rebuild` — перестроение модулей (D101); `workspace` — файлы компаний; `chart_csv` — шаблон плана счетов и импорт CSV; `queries`, `catalog` — чтение для форм; `default_accounts`, `common`.
- **Модули — пакет целиком, чтение и запись (D123):** `application/bank/` (счета, выписки, операции, авансы, ƏDV DH; запись — `commands`, `account_commands`, `deposit_commands` → `BankModule`), `application/conversion/` (`calc` + `commands` → `ConversionModule`), `application/eqaime/` (импорт черновиков `parsing`/`planning`/`drafts`, `portal`, `commands` → `EqaimeModule`); `ledger.bank`/`.conversion`/`.eqaime` — ручки с ленивым импортом. Новый модуль — так же; его таблицы в `MODULE_TABLE`, пакет в `MODULE_CODE` (`test_architecture.py`).
- `src/modern_gl/application/inventory/` — склад: `Inventory` собран так же из групп (`catalog`, `drafts`, `stock`, `receipts` — черновики поступления, `movements`, `sales`, `landed_cost`, `accruals`, `posting`, `rebuild` — перепровести с даты); `model` — константы и dataclass-строки, `amounts` — чистая арифметика.
- `src/modern_gl/reporting/` — отчёты, агрегация в SQL: `reports/` (ОСВ `osv`, по субконто `subconto`, карточка и анализ `card`, анализ и карточка субконто `subconto_analysis`, `subconto_card` — D125, D126), `report_common`, `plaintext` (hledger, D79), `handover` («Передача дел», D81), `inventory/` (склад; `declarations` — «Əlavə xərclər», D85).
- `src/modern_gl/api` — API для разработчиков (D130, `docs/API.md`): `open_company` → `Company`, `cli`; меняется только с `API_VERSION` (`tests/test_api.py`). Файл обмена — `application/exchange/` (`lines` — строки по именам, общие с AI) + `reporting/exchange.py` (`docs/EXCHANGE.md`).
- `src/modern_gl/assistant` — MCP-сервер для AI (D83): `protocol`, `companies`, `answers`, `server`; `drafts` + `draft_tools` — черновики от AI (D84, `--allow-drafts`).
- `src/modern_gl/infrastructure` — движок: `db.py`, `company_file.py` (файл компании движком), `backup.py`; миграции (`migrations/NNNN_*.sql`), шаблоны плана `templates/`, CSV/Excel, порталы (`cbar`, `etaxes`).
- `src/modern_gl/desktop` — интерфейс: `main_window/` (`CompanyFiles` ← `OpenPages` ← `ReportPlaces` ← `MainWindow`; `sidebar`), `document_page/` (документ), `postings/` (таблица ввода), `cell_editing` (ячейки как в 1С: списки с поиском, Enter/Tab, `resolve_choice` — для всех таблиц), `new_cell_value` (новый элемент из ячейки), `rate_note` (курс ЦБА), `period_field` + `period_window` + `day_calendar` (период и даты, D105, D129), `journal_page`, `trade_page` (покупки и продажи), `bank_page/` (банк, D78: счета → выписки по дням со сверкой → выписка; `entry/` — строка ввода; ƏDV DH — `portal`, `deposit_*`) + `bank_operation_page/` (форма операции, F2), `eqaime_import_page` + `eqaime_import_form`, `eqaime_portal_loader`, `portal_login` (e-qaimə с портала; клиент — `infrastructure/etaxes.py`), `inventory_page/` («Склад», D88), `inventory_document_page/` (покупка, продажа, складские документы), `landed_cost_page/` + `landed_cost_report_page` (доп. расходы, D85), `reports_page/` (ОСВ, карточка, план счетов; `table`), `reports_hub/` («Все отчёты», D114), `directories_page/` (справочники; `values` — окно элемента), `conversion_page/`, `opening_balances_page` + `opening_postings`, `account_dialog`, `theme/` (цвета и шрифты), `icons` (Lucide, `icon(name, color, selected=)`), `resources/` (Inter — OFL, Lucide — ISC), `widgets.PageHeader` (`primary()` — одна синяя кнопка, `more()` — «⋯»).

## Правила
- **Слои — только сверху вниз (D122):** `i18n` → `domain` → `infrastructure` → `application` → `reporting` → `desktop`/`assistant`/`api`; слой импортирует себя и слои ниже (`test_architecture.py`), новый пакет верхнего уровня — сначала в `LAYERS`. Языки: код — английский, документы и коммиты — русский, интерфейс — `tr()`. `README.md` — вход для человека, этот файл — карта работы.
- **Инженерные правила (D71, D72)** — перед каждой новой функцией пройти чек-лист `docs/ENGINEERING.md`: модульность и масштабируемость (ядро не знает о модулях, модуль — свой пакет и таблицы), архитектура данных (один источник правды, производное пересчитывается, импорт без дублей), структура базы (`company_id NOT NULL`, составные FK, индекс на каждую ссылку, `CHECK`, миграции неизменны), разработка (тест прежде исправления, транзакция на сценарий, CI зелёный). `tests/test_architecture.py` и `tests/test_database.py` должны быть зелёными; исключения в них не добавлять без записи в «Долг». В ответе пользователю о новой функции — одной строкой, затронула ли она эти правила.
- Деньги — только `int` в копейках; никаких `float`.
- Проведённое не исправляется без следа: в закрытом периоде — только `Ledger.reverse` (красное сторно, D5); в открытом — правка на месте (`Ledger.repost`, D32), отмена проведения или удаление (D19), и полная копия прежнего — в журнал действий (`audit_events`). Документ, сделанный модулем (склад, банк, конвертация) или взятый им (расход партии), правится только там — через представление `document_owners`.
- Каждый запрос фильтрует по `company_id`; новые таблицы — с составными FK `(company_id, id)`.
- Схема меняется только новой миграцией; старые миграции не редактировать.
- **База за одним модулем (D77):** `sqlite3` импортирует только `infrastructure`; типы `Connection`/`Row`/ошибки — из `infrastructure.db`; SQL — общий для SQLite и PostgreSQL (`string_agg`, не `GROUP_CONCAT`; без `PRAGMA`, `rowid`, `INSERT OR`) — следит `test_architecture.py`.
- **Только склад (D90):** `session.stock_only` — страницы книг, корр. счета и ссылки на проводки не показываются; проводки создаются как обычно. Новая страница книг — в `SECTIONS`, но не в `STOCK_SECTIONS` (`main_window/sidebar.py`).
- **Окно не открывает транзакцию (D93):** сценарий — один метод `Ledger`/`Inventory`; правила учёта — в `application`, не в виджете (`test_architecture.py`). Тяжёлое чтение страницы — через `Session.read` (у большой компании — в фоновом потоке, `desktop/background.py`); `fetch(conn)` читает только SQL, `present(data)` заполняет страницу.
- **Только просмотр (D80):** компания может быть открыта снимком без права записи (`session.read_only`). Новая кнопка, которая что-то меняет, — через `hide_when_viewing(session.read_only, …)`; форма документа учитывает `session.read_only`; страница при открытии ничего не пишет — следит `tests/test_read_only_ui.py`.
- Любое изменение логики учёта — с тестом, в котором ожидаемые цифры посчитаны вручную.
- Сообщения об ошибках для пользователя — по-русски.
- **Размер кода** (D70, `docs/CODE_QUALITY.md`): модуль — одна задача; большая страница — форма (`form.py`) + группы-классы по задачам, общие вызовы — «крючки» в форме; пределы — модуль 600 строк, класс 500, функция 80, их проверяет `tests/test_code_size.py`. Список долга `OVER_LIMIT` пуст и не пополняется — сначала разделить. Крупный модуль превращается в пакет с тем же именем; перенос кода — отдельным коммитом, без изменения логики.
- **Дизайн — главный приоритет** (ориентир: Things): светло, много воздуха, боковая панель вместо вкладок, один акцентный синий; отчёты — по `docs/DESIGN.md` (общая таблица, бледная сетка по умолчанию — D127). Цвета и шрифты — только через `desktop/theme.py`. Правила D86: шапка страницы одна — поиск, **одна** синяя кнопка (`PageHeader.primary`), остальное в «⋯» (`PageHeader.more`); **курсива нет**; сделанное тише (`P.muted`), ждущее — громче; заголовки — цветом текста, серый только для пояснений; иконки — только из Lucide (`desktop/icons.py`, новый файл SVG — в `desktop/resources/icons`).
- UI: `src/modern_gl/desktop` (PySide6). Никакого SQL в виджетах — только `application/queries.py`, `application/catalog.py`, `reporting`.
- В тестах UI модальные диалоги подменяются (`no_modal_dialogs`), иначе тест зависнет.
- **Языки**: интерфейс азербайджанский (по умолчанию) и русский. Любой текст для пользователя — через `tr("русский текст {x}", x=...)`; перевод добавить в свой файл `i18n_az/<функция>.py` (`tests/test_i18n.py` упадёт, если забыть). Шаблон плана счетов — в двух файлах `templates/chart_1c77_{az,ru}.csv` с одинаковой структурой.
- Поиск по справочникам — через `i18n.fold` (İ/ı/ş/ç/ə… = i/s/c/e…).
- В тестах текст вводить `type_text()` (`QTest.keyClicks` под Windows падает на не-латинице).
