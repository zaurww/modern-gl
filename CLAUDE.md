# Modern GL

Бухгалтерская программа (главная книга) в стиле 1С 7.7: проводки Дт/Кт с субконто, несколько компаний, параллельные книги (общая / МСФО / налог). Пользователь общается по-русски.

Начало сессии: прочитать `docs/CONCEPT.md` (рамка — меняется только решением пользователя), `docs/STATUS.md` (что есть, что дальше), `docs/ENGINEERING.md`; `docs/ARCHITECTURE.md` — когда работа касается устройства. `docs/DECISIONS.md` целиком не читать — искать решение по номеру (`| D72 |`) или слову; при расхождении решение важнее остальных документов. `docs/history/` — архив, читать только при надобности.
Конец сессии: запись в `docs/history/sessions.md`, сделанное убрать из `docs/STATUS.md`, обновить «Долг» в `docs/ENGINEERING.md`, проверки `docs/CODE_QUALITY.md` (разделы 4 и 5 — код и документы: `tests/test_docs_size.py`); раз в ~5 сессий и перед слиянием большой ветки — полный обзор кода и документов по чек-листам оттуда же.

## Команды
- Тесты: `uv run pytest -q`
- Линтер: `uv run ruff check . && uv run ruff format --check .`
- Типы: `uv run pyright` (тот же движок, что Pylance; должно быть 0 ошибок)
- Программа: `uv run modern-gl` — компании это файлы `*.gl` в «Документы\Modern GL» (`--data <папка>` — другая папка, запоминается); `--demo` добавляет демо-компанию в пустую папку; `--demo-year` — компанию с целым 2026 годом во всех модулях (`demo_year/`)
- Скриншоты для проверки дизайна: `uv run python scripts/screenshots.py <папка>` — после любых изменений UI смотреть их
- Демо в консоли: `uv run python scripts/demo.py`
- Размеры кода (самые большие места): `uv run python tests/test_code_size.py`; документов — `uv run python tests/test_docs_size.py`
- Замеры на большой базе: `uv run python scripts/benchmark.py <папка> --postings 100000`
- AI-помощник (MCP): `uv run modern-gl-mcp` (только чтение; `--allow-drafts` — AI готовит черновики) — подключение в `docs/ASSISTANT.md`

## Структура
- `src/modern_gl/domain` — деньги, даты, ошибки. Без SQL и Qt. Переводы — `src/modern_gl/i18n_az.py`.
- `src/modern_gl/application/ledger/` — все операции записи и правила учёта: `Ledger` собран из групп (`companies`, `currencies`, `subconto`, `chart` (+ `account_types` — классы и типы счетов), `templates`, `documents`, `validation`, `document_import`, `revaluation`, `opening`, `subconto_details`, `account_form`); модули — отдельные объекты над тем же соединением: `ledger.bank` (`bank`, `bank_statements`, `bank_deposit` — ƏDV DH; чтение — `application/bank/`), `ledger.conversion`, `ledger.eqaime` (D93; общее модулей — `module.py`); счёт по умолчанию — `application/default_accounts.py` (по роли/типу, не по коду); общие помощники — `application/common.py`; перестроение проводок всех модулей с даты — `application/rebuild.py` (D101).
- `src/modern_gl/application/inventory/` — склад: `Inventory` собран так же из групп (`catalog`, `drafts`, `stock`, `receipts` — черновики поступления, `movements`, `sales`, `landed_cost`, `accruals`, `posting`, `rebuild` — перепровести с даты); `model` — константы и dataclass-строки, `amounts` — чистая арифметика.
- `src/modern_gl/reporting/reports/` — ОСВ (`osv`), ОСВ по субконто (`subconto`), карточка и анализ счёта (`card`), агрегация в SQL; `reporting/report_common.py` — общее отчётов; `reporting/plaintext.py` — журнал для hledger (D79); `reporting/handover.py` — пакет «Передача дел» (D81); `reporting/inventory/` — склад (`choices`, `stock`, `documents`, `costs`, `declarations` — отчёт «Əlavə xərclər», D85).
- `src/modern_gl/assistant` — MCP-сервер для AI (D83): `protocol` (JSON-RPC по stdio), `companies` (снимки файлов), `answers` (отчёты в JSON), `server` (инструменты, `main`); `drafts` + `draft_tools` — черновики от AI (D84, флаг `--allow-drafts`).
- `src/modern_gl/infrastructure` — SQLite, миграции (`migrations/NNNN_*.sql`), импорт CSV, `workspace.py` (файл на компанию).
- `src/modern_gl/desktop` — интерфейс: `main_window/` (`CompanyFiles` — файл компании ← `OpenPages` — стек страниц ← `ReportPlaces` — как открываются отчёты ← `MainWindow` — какие страницы есть; `sidebar`), `document_page/` (документ: `form`, `rates`, `templates`, `clipboard`), `postings/` (таблица ввода), `cell_editing` (редактирование ячеек как в 1С: списки с поиском, Enter/Tab, поиск в списке `resolve_choice` — для всех таблиц), `new_cell_value` (новый элемент из ячейки), `rate_note` (курс ЦБА в форме), `journal_page`, `trade_page` (покупки и продажи), `bank_page/` (модуль «Банк», D78: счета по группам → выписки по дням со сверкой → выписка; `entry/` — строка ввода; ƏDV DH с портала — `portal`, `deposit_*`) + `bank_operation_page/` (полная форма операции, F2), `eqaime_import_page` (+ `eqaime_import_form`, `eqaime_portal_loader`) + `portal_login` (e-qaimə с портала, клиент — `infrastructure/etaxes.py`), `inventory_page/` (страница «Склад», D88: остатки, карточка товара, все документы), `inventory_document_page/` (форма покупки, продажи и складских документов), `landed_cost_page/` (доп. расходы) + `landed_cost_report_page` (отчёт по декларациям), `reports_page/` (ОСВ, карточка, план счетов; `table` — таблица отчёта), `reports_hub/` («Все отчёты», D114: `catalog` — все отчёты, закреплённые и недавние), `directories_page/` (справочники; `values` — окно элемента), `conversion_page/`, `opening_balances_page` + `opening_postings`, `account_dialog`, `theme/` (все цвета и шрифты; цифры одной ширины — только в таблицах), `icons` (иконки Lucide по имени, `icon(name, color, selected=)`), `resources/` (шрифт Inter — OFL, иконки Lucide — ISC; лицензии рядом), `widgets.PageHeader` (шапка страницы: `primary()` — одна синяя кнопка, `more()` — «⋯»).

## Правила
- **Инженерные правила (D71, D72)** — перед каждой новой функцией пройти чек-лист `docs/ENGINEERING.md`: модульность и масштабируемость (ядро не знает о модулях, модуль — свой пакет и таблицы), архитектура данных (один источник правды, производное пересчитывается, импорт без дублей), структура базы (`company_id NOT NULL`, составные FK, индекс на каждую ссылку, `CHECK`, миграции неизменны), разработка (тест прежде исправления, транзакция на сценарий, CI зелёный). `tests/test_architecture.py` и `tests/test_database.py` должны быть зелёными; исключения в них не добавлять без записи в «Долг». В ответе пользователю о новой функции — одной строкой, затронула ли она эти правила.
- Деньги — только `int` в копейках; никаких `float`.
- Проведённое не исправляется без следа: в закрытом периоде — только `Ledger.reverse` (красное сторно, D5); в открытом — правка на месте (`Ledger.repost`, D32), отмена проведения или удаление (D19), и полная копия прежнего — в журнал действий (`audit_events`). Документ, сделанный модулем (склад, банк, конвертация) или взятый им (расход партии), правится только там — через представление `document_owners`.
- Каждый запрос фильтрует по `company_id`; новые таблицы — с составными FK `(company_id, id)`.
- Схема меняется только новой миграцией; старые миграции не редактировать.
- **База за одним модулем (D77):** `sqlite3` импортирует только `infrastructure`; типы `Connection`/`Row`/ошибки — из `infrastructure.db`; SQL — общий для SQLite и PostgreSQL (`string_agg`, не `GROUP_CONCAT`; без `PRAGMA`, `rowid`, `INSERT OR`) — следит `test_architecture.py`.
- **Только склад (D90):** `session.stock_only` — страницы книг, корр. счета и ссылки на проводки не показываются; проводки создаются как обычно. Новая страница книг — в `SECTIONS`, но не в `STOCK_SECTIONS` (`main_window/sidebar.py`).
- **Окно не открывает транзакцию (D93):** сценарий — один метод `Ledger`/`Inventory`; правила учёта — в `application`, не в виджете (`test_architecture.py`). Тяжёлое чтение страницы — через `Session.read` (у большой компании — в фоновом потоке, `desktop/background.py`); `fetch(conn)` читает только SQL, `present(data)` заполняет страницу.
- **Только просмотр (D80):** компания может быть открыта снимком без права записи (`session.read_only`). Новая кнопка, которая что-то меняет, — через `hide_when_viewing(session.read_only, …)`; форма документа учитывает `session.read_only`; страница при открытии ничего не пишет — следит `tests/test_read_only_ui.py`.
- Любое изменение логики учёта — с тестом, в котором ожидаемые цифры посчитаны вручную.
- Сообщения об ошибках для пользователя — по-русски.
- **Размер кода** (D70, `docs/CODE_QUALITY.md`): модуль — одна задача; большая страница — форма (`form.py`: поля строятся методами) + группы-классы по задачам, общие вызовы — «крючки» в форме; пределы — модуль 600 строк, класс 500, функция 80, их проверяет `tests/test_code_size.py`. Список долга `OVER_LIMIT` пуст и не пополняется — сначала разделить. Крупный модуль превращается в пакет с тем же именем, `__init__` реэкспортирует прежний API; перенос кода — отдельным коммитом, без изменения логики.
- **Дизайн — главный приоритет** (ориентир: Things от Cultured Code): светло, много воздуха, боковая панель вместо вкладок, крупные заголовки, один акцентный синий, без сеток «как в Excel». Цвета и шрифты — только через `desktop/theme.py`. Правила D86: шапка страницы одна — поиск, **одна** синяя кнопка (`PageHeader.primary`), остальное в «⋯» (`PageHeader.more`); **курсива нет**; сделанное тише (`P.muted`), ждущее — громче; заголовки — цветом текста, серый только для пояснений; иконки — только из Lucide (`desktop/icons.py`, новый файл SVG — в `desktop/resources/icons`).
- UI: `src/modern_gl/desktop` (PySide6). Никакого SQL в виджетах — только `application/queries.py`, `application/catalog.py`, `reporting`.
- В тестах UI модальные диалоги подменяются (`no_modal_dialogs`), иначе тест зависнет.
- **Языки**: интерфейс азербайджанский (по умолчанию) и русский. Любой текст для пользователя — через `tr("русский текст {x}", x=...)`; перевод добавить в `i18n_az.py` (`tests/test_i18n.py` упадёт, если забыть). Шаблон плана счетов — в двух файлах `templates/chart_1c77_{az,ru}.csv` с одинаковой структурой.
- Поиск по справочникам — через `i18n.fold` (İ/ı/ş/ç/ə… = i/s/c/e…).
- `QTest.keyClicks` в PySide под Windows падает на кириллице и азербайджанских буквах — в тестах вводить через `type_text()`.
- Если программа запущена, `uv run` не может обновить `modern-gl.exe` — использовать `uv run --no-sync` или закрыть программу.
