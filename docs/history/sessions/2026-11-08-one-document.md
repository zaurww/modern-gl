# 2026-11-08 — claude/one-document

Пользователь попросил обзор проекта как специалист по базам, разработке и учёту, затем —
«начинаем делать». Вывод обзора: ядро сильное (по целостности ближе к SAP), неудобство — от
четырёх моделей документа и пяти форм ввода; план — один документ, один каркас формы,
реестр расчётов, затем одна нумерация.

- Шаг 1 (D213): миграция 0068 — вид документа модуля в `document_owners`;
  `application/document_kinds.py` — одно место названий («Alış №1», «Bank məxarici №13»).
- Журнал: колонка «Вид», свой номер документа, поиск по виду и своему номеру.
- Карточка счёта, карточка субконто, акт сверки: колонка «Документ» вместо номера книги.
- Форма ручного документа — «Əməliyyat №13».
- Номер книги остался ключом: AI-помощник и обмен работают с ним.
- Дальше в той же сессии: уведомления «Keçirildi: Əməliyyat №14»; отчёт e-qaimə и сверка с
  порталом — названия документов (`name_rows`, только для страницы, не для расчёта банка);
  «уже есть: Alış №3» при загрузке e-qaimə; три копии словаря видов в `desktop` — на
  `document_kinds`. F7 и «Bu gün» номеров не показывают.
- Дальше: шаг 2 — общий каркас формы документа.
