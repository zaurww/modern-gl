# 2026-11-03, ветка release-0-1-1 (D189)

Разговор о стеке: «Python-десктоп даётся тяжело» — где именно (сборка, отзывчивость, большие
таблицы, вид), что легче (Tkinter, pywebview, Textual). Пользователь замечает задержки в
Qt и просил макет на Tkinter: собран настоящий экран ОСВ на Tkinter в палитре программы
(scratchpad сессии, в проект не вносился). Голые окна: Tk 0,4 с / 30 МБ, Qt 0,7 с / 66 МБ —
разница не та, что чувствуется как лаг; причина задержек — в программе (чтение в главном
потоке, перестроение страниц), решено **оставить Qt** и замерить задержки профайлером,
когда пользователь назовёт страницы.
Пользователь: дизайн в стиле Things — первоначальная задумка; документы — не истина в
последней инстанции, отходить и экспериментировать можно (записано в память Claude).
Установка у коллеги (не технарь): репозиторий **сделан публичным** (`gh repo edit`) —
Actions бесплатны, Release по ссылке; лицензии нет (все права защищены). Документы остаются
по-русски, в README — строка по-азербайджански. Выпуск v0.1.1: CHANGELOG (D190 и мелочи
после 0.1.0), STATUS (вопрос установщика снят; «Дальше» — обновление из программы),
`OPEN.md` — решено. Сборка — `scripts/release.py 0.1.1 --push` из master.

**Позже, ветка portal-webengine.** Коллега поставил 0.1.1, завёл банковские счета, скачал
курсы, а «Alış → загрузить с портала» упало: `No module named PySide6.QtWebEngineWidgets` —
`modern-gl.spec` исключал QtWebEngine ради размера, а окно портала и есть этот браузер
(ленивый импорт, поэтому тесты не видели). Исключение снято; `sign_in` в сборке без
браузера показывает сообщение, не падает; тест `test_the_build_excludes_nothing_the_program_imports`;
локальная сборка PyInstaller проверена на `QtWebEngineProcess.exe`. Выпуск 0.1.2.

**Ещё позже, ветка portal-view.** В 0.1.2 окно портала упало уже само: `AttributeError:
'PortalLoginDialog' object has no attribute 'view'` — кнопка «Обновить страницу»
подключалась к `self.view.reload` до создания браузера (с D115; окно ни разу не строилось в
тестах — исключено из `test_window_design`). Браузер создаётся первым; `AA_ShareOpenGLContexts`
до `QApplication` (Qt 6); `tests/test_portal_login.py` строит окно с подменным движком.
Живая проверка на Windows: окно открылось, страница портала загрузилась. Выпуск 0.1.3.
Пользователь: «можно, чтобы обновления появлялись в интерфейсе» — да, следующая ветка
(STATUS «Дальше» п. 10).

**Ветка updates (D191).** Пользователь: «можно, чтобы обновления появлялись в
интерфейсе и не приходилось заново всё скачивать и устанавливать?» Сделано: раз в день
`github_releases.fetch_latest` в фоне → `updates.newer_release` → строка `sidebar.new_version`
«Вышла версия … — обновить» → скачивание с процентом → `cmd /c start /wait setup /SILENT
/CLOSEAPPLICATIONS & start modern-gl.exe`, программа выходит и возвращается обновлённой.
Из исходников не проверяет. Тесты с подменными GitHub и пулом «сразу». Выпуск 0.1.4 — её
коллега ставит руками в последний раз.

**Ветка update-hourly.** 0.1.5 — выпуск без изменений для живой проверки D191. Пользователь:
«нужно, чтобы обновления показывались сразу: работник нашёл ошибку, я исправил — ждать целый
день нельзя». Проверка — при каждом запуске и раз в час (`QTimer`, останавливается, когда
версия найдена); `due` и `UPDATES_CHECKED` убраны. Выпуск 0.1.6.
Живая проверка 0.1.4 → 0.1.5 у пользователя: «отлично работает». Кнопка — красная
(`dangerSolid`) по просьбе пользователя.
Промах 0.1.4: `subprocess.Popen(["cmd", "/c", 'start "" …'])` — Python экранирует
кавычки как `\"`, cmd их не читает → «Windows cannot find '\'», чёрное окно cmd, установщик
не запущен. `install_command` возвращает одну строку; проверено на машине с `rundll32`
вместо установщика (список виснет на диалоге, строка — код 0). Урок: команду для cmd —
строкой, и живая проверка цепочки до выпуска.
