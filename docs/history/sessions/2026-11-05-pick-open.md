# 2026-11-05, ветка pick-open

Пользователь вводит импорт: покупка по декларации, потом доп. расходы.

- **«Только после ввода буквы появляется [список], что неудобно»** — поле основания
  покупки (E-qaimə / Bəyannamə / ждёт e-qaimə). Поле выбора `PickBox` открывало список
  только при наборе и по ↓/F4. Теперь щелчок открывает весь список, выбранное подсвечено;
  поле только для чтения не открывает. `SuggestBox` (номер e-qaimə) по щелчку предлагает
  без подсветки — набранное остаётся (`desktop/pick.py`, `_show_on_click`).
- **«Появился артикул (sku), нужен ли он?»** — нет: в окне товара поле необязательное,
  теперь это сказано в нём самом («необязательно», как код в окне счёта).
- **«Здесь есть Maddə, туда ничего не вписывается»** — доп. расходы: список статей пуст,
  пока виды расходов не добавлены в «Склад → ⋯», а ячейка нового не принимала. Теперь
  набранное имя предлагается как «+ Добавить «…»» и становится статьёй на месте (D49;
  `landed_cost_page/table.py`, `page._add_cost_type`; тест в `test_landed_cost.py`).
  Счёт 15 в расходе до ввода банка — можно: Дт товар / Кт 15, остаток счёта не проверяется.
- Проверено: `tests/test_uniform_entry.py` (три новых теста, без правки падают),
  `test_inventory.py`; весь набор — 1815 прошли; ruff, pyright — 0. В живом окне не смотрели.
- **Открыто (за пользователем):**
  - другие основания покупки — «акт, инвентаризация, прочее». Вид номера хранится в
    проводках (`invoice_kind`, `CHECK` допускает только `customs`) и решает, что видят
    сверка с порталом и ƏDV — нужно решение, что значит каждый вид;
  - ƏDV таможни: колонка «ƏDV» в доп. расходах проводит Дт 19 / Кт 76 без номера
    декларации, в ручном документе и банке пометить номер как декларацию негде —
    «ƏDV к зачёту» такую сумму под декларацией не покажет (STATUS: «НДС таможни без №»).
