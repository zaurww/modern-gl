# Склад: сравнение с другими программами и план переработки

Сессия 2026-10-26, ветка `claude/anbar`. Продолжает D121 («сначала сравнить, потом отчёты»).
Устройство модуля — `docs/INVENTORY.md`.

## 1. Что есть у нас
- Документы: начальные остатки, покупка (товары, услуги, ОС, ƏDV, валюта, e-qaimə, «ждёт
  e-qaimə»), продажа (товары, услуги), mədaxil по причине, списание, перемещение, доп.
  расходы по партии (ERPNext Landed Cost Voucher).
- Себестоимость — скользящая средняя по (товар, склад); документ задним числом пересчитывает
  следующие сразу; доп. расходы делятся на остаток и уже проданное.
- Покупка и продажа — один документ: склад и проводки сразу (как 1С БП «Поступление»,
  ERPNext «Update Stock»). Режим «Только склад» (D90).
- Отчёты: остатки на сегодня (страница «Склад»), карточка движений выбранной строки,
  «Доп. расходы по декларациям» (D85). **Ведомости за период, остатков на дату, прибыли по
  товарам, сверки склада с книгой — нет.**
- Нет: возвратов, инвентаризации, второй единицы, минуса, минимального остатка, списка
  товаров без остатка на странице «Склад».

**Вывод.** По записи данных мы на уровне простых программ и проще больших (без цепочек
заказ → приём → счёт, без транзитных счетов, один метод стоимости — это сознательно не
меняем). Отстаём в трёх местах: **отчёты** (у всех есть ведомость, остатки на дату и
прибыль по товарам), **обычные операции склада** (возврат, инвентаризация) и **удобство
ежедневной работы** (вторая единица, минимальный остаток, список товаров).

Лишнее для нас: заказы и резервы, многошаговая приёмка (Odoo, 1С УТ ордерный склад),
«физический» и «учётный» остаток (Zoho), выбор метода у товара, LIFO, партии и серии,
производство с картой, пакетная проводка (Logo), ячейки склада.

## 3. План
**Этап 1 — отчёты (смысл данных не меняют; сделано в этой ветке).**
1. «Ведомость по складу»: период, по товарам (под товаром — склады) или по складам;
   количество и сумма — начало / приход / расход / конец (ERPNext Stock Balance, inFlow
   Movement Summary). Конец периода — это и «остатки на дату». Строка проверки — стоимость
   склада против остатка счетов товаров в книге. Двойной щелчок → «Карточка товара» →
   документ.
2. «Карточка товара»: товар на складе за период — начальный остаток, каждое движение с
   источником, приход, расход, остаток (ERPNext Stock Ledger).
3. «Валовая прибыль по товарам» (Logo «Ayrıntılı maliyet analizi», ERPNext Gross Profit):
   продано, выручка без ƏDV, себестоимость (с доп. расходами, пришедшими после продажи),
   прибыль, %; по товарам или по покупателям; двойной щелчок → продажи товара.
4. Все три — в «Все отчёты», группа «Склад», и в меню «Отчёты ▾» страницы «Склад»; «Доп.
   расходы по декларациям» переезжают в группу «Склад».

**Этап 2 — операции склада (меняют смысл данных: нужно решение пользователя).**
1. Возврат поставщику и от покупателя — по исходному документу (цена возврата поставщику
   — цена прихода; от покупателя — себестоимость той продажи), сторно выручки и ƏDV.
2. Инвентаризация: склад и дата → «Заполнить» учётными остатками → факт → излишки
   (mədaxil «Излишки») и недостача (списание) одной кнопкой (1С, Katana — по складу).
3. Вторая единица у товара (закупки или продажи) с коэффициентом (inFlow); учёт — в основной.
4. Минимальный остаток у товара → «Ниже минимума» на «Bu gün» и кнопка «Покупка» с этими
   товарами (Zoho).
5. Минус — оставить запрет (Katana и NetSuite прямо пишут, что себестоимость в минусе
   неверна); вернуться при реальном случае «продажа раньше прихода».

**Этап 3 — страница «Склад».** Список товаров с нулевым остатком тоже (фильтр «с
остатком»), поиск, дата остатков; семь кнопок операций — в меню «+ Документ ▾» (одна
синяя кнопка — D86); минимальный остаток — колонкой.
