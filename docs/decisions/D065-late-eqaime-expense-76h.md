# D65 — Расход за прошлый месяц по поздней e-qaimə — через счёт 76H «Начисленные расходы»
Статус: принято
Дата: 2026-10-21

## Контекст
—

## Решение
**Расход за прошлый месяц по поздней e-qaimə — через счёт 76H «Начисленные расходы»** (сессия 20, вопрос пользователя: услуга сентября, фактура октября; миграция 0031). Как GR/IR в SAP и Received Not Billed в NetSuite; автосторно 1-го числа (QuickBooks, Xero) отклонено: если фактура опоздает больше чем на месяц, расход «прыгает». В покупке поле «Расход за» (месяц документа или один из 12 предыдущих, хранится последним днём месяца, `inventory_documents.expense_date`); показывается, когда есть строка без товара. При проведении строки без товара начисляются последним днём того месяца отдельным документом GL (Дт счёт затрат / Кт 76H [поставщик]; `accrual_document_id`), а сама покупка закрывает начисление: Дт 76H / Кт 60 вместо Дт затрат / Кт 60; НДС и долг поставщику — датой e-qaimə. Товары не начисляются (склад — датой документа). Начисление принадлежит покупке: правится, распроводится и удаляется только вместе с ней; в журнале открывает покупку. Новое начисление в закрытый период запрещено; уже сделанное при пересчёте не трогается, если не изменилось. Новый тип счёта `accrued_expenses` (не расчётный — отчёт «E-qaimələr» не считает Дт 76H / Кт 60 оплатой) и роль; 76H в обоих шаблонах (в 1c77 — под 76); компания без такого счёта получает 76H при первом начислении. Дальше (не сделано): начисление заранее для ожидаемых фактур (аренда, связь) и отчёт «Открытые начисления». В окне загрузки e-qaimə с портала — колонка «Расход за» у покупок со строками без товара (тот же выбор месяца, `InvoicePlan.expense_date`).
