## Решение
**AI-помощник — MCP-сервер, сначала только чтение** (сессия 33; вопрос пользователя: «клиент хочет AI для помощи во вводе и проверках»). Программа не встраивает свой чат и не выбирает модель: она отдаёт книги как инструменты по открытому протоколу MCP, а клиент подключает их к Claude Desktop или любому MCP-клиенту (можно и к локальной модели). Сервер `modern-gl-mcp` (stdio) читает те же компании, что программа (её папка и запомненные файлы — из настроек, `infrastructure/app_settings.py`, без Qt), каждую — **снимком только для чтения** (D80): писать он не может по построению, файл не блокируется, снимок обновляется, когда файл меняется. Инструменты: компании, план счетов, ОСВ, карточка, анализ счёта, ОСВ по субконто, журнал за период с поиском, документ по номеру, справочник (VÖEN, метки, группы), e-qaimə (неоплаченные). Суммы — строки в манатах («1234.50»), не float; длинные списки обрезаются с `left_out`. Протокол — свой небольшой (`assistant/protocol.py`: initialize, ping, tools/list, tools/call), **без новой зависимости**: официальный SDK тянет pydantic, starlette, uvicorn ради четырёх методов. Модуль `assistant` — адаптер над `reporting`/`queries`, ядро о нём не знает. **Дальше:** (2) черновики от AI — только через `Ledger`, никогда не проводит сам, пометка источника; (3) распознавание счетов/фото и подсказка счетов для банка и e-qaimə; (4) встроенный чат — если понадобится. Данные уходят в облако только по выбору клиента (какой AI он подключил).
