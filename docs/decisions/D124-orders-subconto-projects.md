## Решение
**Турагентство и проекты — справочник «Sifarişlər» третьим субконто, не договор и не модуль** (сессия 51; вопросы пользователя: учёт турагентства, «müqavilə как номер кейса?», «3 субконто не многовато?», Layihələr). Кейс (заявка клиента) виден у клиента (62.1), у поставщиков (60.1) и в выручке (90.1 / 46); договор принадлежит контрагенту и рядом с поставщиком не проходит (`_validate_owners`), поэтому — пользовательский справочник без владельца (D20) третьим субконто, обязательный при проведении. То же для строительства, услуг, юристов — имя даёт компания («Layihələr», «Obyektlər»). Схема агента: деньги клиента транзитом 62.1 → 60.1, выручка — комиссия. Проверено без изменений кода — `tests/test_travel_agency.py`: ядро, ОСВ по субконто по 3-й позиции, формы покупки и продажи (колонка «Sifarişlər» по строке; в продаже одна — значение покупателя идёт и на 90.1). Не хватает: отчёт «карточка заказа» по всем счетам; банк — зачёт аванса знает только контрагента и договор (`bank._partner_subconto`); строка аванса берёт субконто по виду (`advances.carried_over`, та же сессия). Измерение строки (D36) не нужно, пока третьего места хватает.
