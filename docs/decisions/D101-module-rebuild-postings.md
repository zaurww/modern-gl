## Решение
**Модуль умеет перестроить свои проводки с даты — правило для всех модулей** (сессия 40; пользователь: после тестов находятся ошибки, нужно «перепровести всё» и массово править; изучены ERPNext Repost Item Valuation / Stock Value Comparison / Repost Accounting Ledger, Xero Find & Recode, QuickBooks Reclassify и Client Data Review, Odoo, Zoho, 1С «Групповое перепроведение»). Выбран один общий механизм на будущее: фильтр → действие → предпросмотр «было/стало» → применить одной транзакцией → отменить пакет; действия — «перепровести с даты» (ошибка в правилах или настройках) и «изменить выделенное» (ошибка в данных). **Сейчас — только правило** (интерфейс, сверка с поиском даты расхождения и групповая правка — позже, когда каркас и модули готовы): модуль, который делает GL-документы (`document_owners`, роль `made`), имеет `rebuild_postings(company_id, since) -> list[int]` — строит их заново из своих документов с даты, номера сохраняются, изменённое — `repost` в журнале действий с прежними проводками, ничего не изменилось — следа нет; закрытый период не трогается (`ledger/module.rebuild_start`); ошибка называет документ и откатывает всё. Банк и конвертация — `_rebuild_module_document` (изменённый документ проходит `_require_changeable`); склад — `inventory/rebuild.py`: все проведённые с даты снимаются и проводятся заново по порядку, как после правки задним числом. Все модули сразу — `application/rebuild.py` (`module_rebuilders`, `rebuild_postings`, одна транзакция). Страж — `tests/test_rebuild.py`: модули с ролью `made` в представлении = `module_rebuilders`; перестроение целого демо-года (все модули, закрытое полугодие открыто) ничего не меняет; ручные цифры — курс банка, курс конвертации, счёт себестоимости.
