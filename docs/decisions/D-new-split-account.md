# D-new — Счёт с проводками становится группой: «Разделить счёт»
Статус: принято (опирается на D5, D21, D22, D62)
Дата: 2026-10-29

## Контекст
Пользователь: «2 поступления отнёс к счёту 75. Тогда он не был групповым… теперь нужно
сделать его групповым и добавить субсчета. Заранее предвидеть нельзя… нужен механизм,
которому можно доверять и который ничего не сломает»; «речь не только о 75, а о всех
счетах». Было: счёт с проводками не мог стать группой.

## Решение
- «Добавить субсчёт…» у счёта, который не группа: окно «Сделать счёт N группой» — код и
  название первого субсчёта (предложен N.1, название прежнее). Сразу после — форма
  следующего субсчёта (N.2).
- Как: новая строка-группа берёт код, название, место в плане, класс, тип, двусторонность,
  валюту прежнего счёта; **сам счёт (тот же id) становится первым субсчётом** — с новым
  кодом и названием. Проводки, операции модулей, роли счетов, шаблоны, начальные остатки
  ссылаются на id — ни одна строка учёта не меняется, закрытые периоды не трогаются.
  Одна транзакция, в журнал действий — «split» с прежним и новым.
- Галочка «Группа» в карточке счёта с проводками по-прежнему не ставится; сообщение
  ведёт к «Добавить субсчёт…».

## Последствия
`Ledger.split_account` (`application/ledger/chart.py`), `desktop/split_account_dialog.py`.
Тесты: `tests/test_split_account.py` (ОСВ до и после посчитана вручную).
Обратно: группа без субсчетов снова становится счётом; группа с одним субсчётом — нет
(слить счета — отдельная задача, если понадобится).
