## Решение
**Долг кода 2, 6, 9–11 погашен: модули — объекты, сценарий — один метод, правила — в application, счета — по типу, большие компании — в фоне** (сессия 38; пользователь: «на верху были пункты слабые места 6, 9–11, 2»). (1) **Модули `Ledger`** (долг 2): ядро — наследованием групп, банк (с выписками и авансами), конвертация и e-qaimə портала — `ledger.bank`, `ledger.conversion`, `ledger.eqaime`: объекты над тем же соединением и `actor`, один на `Ledger` (`BankModule`, `ConversionModule`, `EqaimeModule`); это основа включения модуля для компании (D30). (2) **Окно не открывает транзакцию** (долг 10): `Ledger.offset_all_advances` / `plan_advance_offsets`, `update_and_post`, `add_detailed_value` / `save_detailed_value` (`ValueDetails`), `save_account_form` (`AccountForm`; первый субсчёт делает родителя группой — правило было в окне), `Inventory.edit_item`, `set_bank_account(name=)`, `quick_entry.save_quick_entry`; страж — `test_windows_open_no_transaction`. (3) **Правила учёта из окон** (долг 9): НДС строки и ставка нового документа (`inventory.line_vat`, `default_vat_rate`), кредитовый начальный остаток «Дт 00 / Кт счёт» (`ledger.opening_posting`), вторая операция «ƏDV депозит» и раздел суммы e-qaimə (`bank.vat_deposit_part`, `split_by_deposit`), официальный (кросс-)курс конвертации (`conversions.official_rate`), зачёт авансов, сохранение быстрой строки; цифры — `tests/test_window_rules.py`. (4) **Счёт по умолчанию — по роли или типу** (долг 11, `application/default_accounts.py`): покупка — первый счёт типа «Поставщики», продажа — «Покупатели», списание — роль себестоимости, остатки склада «только склад» — нераспределённая прибыль, новый банковский счёт — по виду (карта — 55, если есть), переоценка — роли курсовых разниц; коды — последнее средство для плана без типов. Исправляет план 1С 7.7: там 46 — запасы, 80 — уставный капитал. (5) **Большая база** (долг 6): `scripts/benchmark.py` строит компанию на N проводок и меряет отчёты. На 100 000: соединение «сначала проводки» (`FROM postings p CROSS JOIN docs WHERE docs.id = p.document_id`, общий SQL) — ОСВ 1,6 → 0,5 с, по субконто 1,5 → 0,3 с; выписки банка — накопленными суммами (3,1 → 1,0 с). С 20 000 проводок «Bu gün», журнал, ОСВ, отчёты счёта и e-qaimə читаются в одном фоновом потоке на своём соединении только для чтения (`Session.read`, `desktop/background.py`): окно отвечает (пауза ≤ 150 мс), последнее обновление побеждает; два читателя сразу не запускаются — GIL делает их в разы медленнее (2,5 с одно, 24 с два). (6) **Остаток долга 6** (там же): журнал показывает один год — рабочей даты (меню «2026 ▾»: другие годы, «Все годы»; сохранённый документ приводит свой год); страница банка читает уровни через `fetch/present` и `Session.read` (строка ввода получает курсор, когда выписка показана); пересчёт склада — запись, в фон не уносится (решение пользователя: «ускорить»): индекс `inventory_lines (company_id, item_id)` (миграция 0039) и справочник (товар, склад, счёт, субконто) на время одного пересчёта — `InventoryBase._keeping_catalog`; демо-год, весь год заново: 2,9 → 1,3 с, результат сверен до копейки с прежним.
