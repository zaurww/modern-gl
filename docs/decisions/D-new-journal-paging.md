# D-new — Журнал читается порциями, поиск — в запросе
Статус: принято
Дата: 2026-10-27

## Контекст
Аудит: журнал читал выбранный год целиком (на базе в 100 000 проводок — 33 449 строк,
открытие ~0,42 с) и искал `QSortFilterProxyModel` по прочитанному (~0,84 с на букву);
`canFetchMore` в проекте не было. Долг 6, D24: решать по замерам.

## Решение
**Модель журнала держит порцию по 500 документов вокруг показанного** (только что
сохранённого, текущего, иначе конец года — выбор строки как раньше): старшие
догружаются при прокрутке вверх (строки на экране остаются на месте), младшие —
`canFetchMore`/`fetchMore` при прокрутке вниз. Порции — keyset по (`doc_date`, `number`),
порядок журнала, тот же фильтр года, без `OFFSET`. **Поиск — условие запроса**: по
содержанию (SQL-функция `fold` = `i18n.fold`, İ/ı/ş = i/s), номеру и дате ДД.ММ.ГГГГ —
находит и непрочитанное; сумма, книга, автор, статус больше не ищутся. Авторы — для
порции, «несколько авторов» — одним `COUNT(DISTINCT)`. Чтение — `Session.read` (D93).
Замер: открытие 0,42 → 0,11 с, поиск 0,84 → 0,09 с.
