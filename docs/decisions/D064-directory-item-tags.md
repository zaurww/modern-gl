# D64 — Метки элементов справочников — для отчётов «по признаку», без субсчетов
Статус: принято
Дата: 2026-10-21

## Контекст
—

## Решение
**Метки элементов справочников — для отчётов «по признаку», без субсчетов** (сессия 20, миграция 0030). Вопрос пользователя: «отчёт по иностранным контрагентам / по всем поставщикам аренды / по связанным компаниям — нужно ли отделять 60.2?». Нет: признак контрагента не должен зависеть от того, на какой субсчёт провёл бухгалтер (так в QuickBooks/Xero/Zoho: один счёт поставщиков, отбор по свойствам контрагента или тегам — Zoho reporting tags). Метка — свойство компании (`tags`), у элемента их сколько угодно (`subconto_value_tags`), в отличие от группы (одна на элемент, D60); у группы меток нет. Удаление метки или элемента снимает связи (`ON DELETE CASCADE`; `where_used` такие ссылки не считает). Имена уникальны без учёта регистра и İ/i (`fold`). UI: «пилюли» в окне элемента (+ Метка; меню пилюли — переименовать/удалить), «Метки…» в меню любого элемента, колонка «Метки» в справочнике; в ОСВ по субконто — поле «Метка» (видно, когда у элементов справочника есть метки). «Поставщики аренды» — не метка, а отбор по корреспонденции (Дт 26 [Аренда] / Кт 60) — следующий шаг.
