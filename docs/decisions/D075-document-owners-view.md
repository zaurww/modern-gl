# D75 — Владелец GL-документа — представление `document_owners`, ядро читает только его
Статус: принято
Дата: —

## Контекст
—

## Решение
**Владелец GL-документа — представление `document_owners`, ядро читает только его** (сессия 25, долг №1 `ENGINEERING.md`, до модуля ОС; развивает D71). Миграция 0032 создаёт VIEW из таблиц модулей: `(company_id, document_id, module, role, owner_number)`, роль `made` — документ создан модулем и правится там, `uses` — модуль взял документ в свой (расход партии) и его сначала надо убрать оттуда. Выбрано представление, а не таблица (в ней пришлось бы дублировать ссылки, которые уже хранят модули, — два источника правды) и не регистрация проверок в коде (защита зависела бы от того, какой модуль импортирован). Тексты сообщений модули регистрируют сами (`explain_owner`); без них ядро отказывает общим сообщением. Новый модуль, создающий или использующий GL-документы, пересоздаёт представление своей миграцией (`DROP VIEW` + `CREATE VIEW`). Сессия 47 (долг 12): колонка `owner_id` (миграция 0044) — по ней журнал, выписка банка и главное окно узнают документ модуля через `queries.document_owner`, не читая таблицы модулей.
