# D176 — Каждый UPDATE и DELETE называет компанию: правило под тестом, как клиент в SAP
Статус: принято (уточняет D71, D72)
Дата: 2026-10-27

## Контекст
Правило «каждый запрос фильтрует по `company_id`» держалось на аккуратности: 76 записей
меняли строку по одному `id`. При файле на компанию (D18) это безопасно, но путь к общему
серверу (D24, D77) открыт — там такая запись задела бы чужую фирму. SAP не полагается на
разработчика: поле клиента `MANDT` подставляется в каждый запрос самим слоем базы.

## Решение
- Каждый `UPDATE` и `DELETE` в `src/` называет `company_id` в `WHERE`; в `companies`
  компания — сам `id`. Проверяет `test_every_write_names_its_company`
  (`tests/test_architecture.py`), в том числе с таблицей из f-строки.
- Помощникам склада, менявшим документ по одному `id`, добавлен `company_id`.
- На сервере (PostgreSQL) к этому добавится row-level security — по решению о сервере.

## Последствия
Логика учёта не менялась; все тесты зелёные. Новая запись без компании не пройдёт CI.
