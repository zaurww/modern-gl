# D192 — «Доход за» в продаже: доход прошлого месяца по поздней e-qaimə — через счёт 76G «Начисленные доходы»
Статус: принято
Дата: 2026-11-03

## Контекст
Пользователь после переноса «Расход за» в конец строки покупки: «В продажах тоже есть этот
момент?» — «Хорошо, тогда добавь «Доход за» в продажу». Зеркало D65; было в `BOOKS.md`,
«дальше» п. 2.

## Решение
- **«Доход за»** у строки-услуги продажи: то же поле и окно диапазона, что у покупки
  (D136); столбец последний. У товара месяца нет.
- **Начисление** последним днём месяца: Дт 76G [покупатель] / Кт выручка на сумму без ƏDV;
  продажа закрывает его Дт 62 / Кт 76G. ƏDV — датой e-qaimə. При выручке «с ƏDV» (Дт 62 / Кт
  46, D61) часть ƏDV остаётся Дт 62 / Кт 46 датой продажи и гасится Дт 46 / Кт 68.2 в том
  же месяце. Правила владения, правки и закрытого периода — как у покупки.
- **Тип счёта `accrued_income`** («Начисленные доходы», актив, контрагенты), роль, 76G в
  шаблонах, появляется при первом начислении. Не расчётный (отчёт «E-qaimələr»); в ОПиУ —
  сторона покупателя. Миграция 0062 перестраивает `accounts` и её триггеры.
- В окне загрузки e-qaimə с портала столбец месяца («Расход / доход за») — и у продаж
  с услугами (ветка `import-income`). Не сделано: закрытие начисления за закрытый месяц.
