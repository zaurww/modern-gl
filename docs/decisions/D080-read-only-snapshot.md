# D80 — Режим «только просмотр»: снимок файла в памяти
Статус: принято
Дата: 2026-10-22

## Контекст
—

## Решение
**Режим «только просмотр»: снимок файла в памяти** (сессия 31; первый шаг к работе нескольких людей с одной компанией). Меню компании → «Открыть для просмотра…»: файл читается в память (`db.open_snapshot`, `Workspace.view`), там же обновляется до текущей схемы, и соединение запрещает любую запись (`PRAGMA query_only`). Сам файл не меняется, не блокируется, не обновляется и не копируется в резервные — поэтому можно смотреть файл коллеги, даже открытый им (свежие проводки берутся из его WAL), в том числе в общей папке только для чтения; новое — «Перечитать файл». Гарантия — в базе: `db.transaction` сразу бросает `ReadOnlyError` с текстом для пользователя, запись мимо транзакции отвергает SQLite. Интерфейс: метка «Только просмотр» под названием компании, в заголовке окна; формы документов показываются как проведённые в закрытом периоде (`read_only` формы учитывает `session.read_only`); кнопки создания, проведения, удаления, импорта скрыты (`widgets.hide_when_viewing`); `new_*` окна отказывают с сообщением в строке состояния. Страница, которая при открытии сама что-то создаёт (счёт начальных остатков), в просмотре этого не делает. Не выбрано: открыть сам файл `mode=ro` (SQLite по сети в WAL ненадёжен, старый файл нельзя обновить, на защищённой папке не открывается). Правка вторым человеком — только через сервер (D77).
