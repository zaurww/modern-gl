# D224 — Обновление схемы не меняет цифры учёта: обороты и склад сверяются до и после
Статус: принято (дополняет D148)
Дата: 2026-11-25

## Контекст
Пользователь: «боюсь, что обновления могут что-то сломать». D148 защищает от сбоя миграции
(всё или ничего), но не от миграции, которая прошла и тихо изменила цифры — перестроила
таблицу с неверным соединением, потеряла или удвоила строки. Такое замечают через недели.

## Решение
- `db.migrate` внутри транзакции обновления читает «слепок книги» до ждущих миграций и после
  них (`infrastructure/books_digest.py`): обороты Дт и Кт каждого счёта по месяцам
  (проведённые документы) и количество и сумму каждого товара на каждом складе.
- Слепки разошлись — обновление откатывается, файл остаётся файлом прежней версии; человек
  видит `UpgradeError`: какой счёт и месяц, сколько расхождений, где копия. Работает везде,
  где файл обновляется: окно, просмотр (D80), API, AI.
- Миграция, которая **должна** изменить цифры, говорит об этом строкой
  `-- books-change: <причина>`; такое обновление не сверяется.
- Чтение — простым SQL по колонкам, которые есть у таблиц с их появления (0001, 0007).

## Последствия
`infrastructure/books_digest.py`, `db.migrate`; тест `tests/test_upgrade_check.py` (обороты
посчитаны вручную). ENGINEERING 3.7. Цена — два агрегата по проводкам на обновление.
