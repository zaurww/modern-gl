# D179 — Стек не меняется: Python, SQLite-файл, PySide6; ядро не знает о Qt
Статус: принято (опирается на D9, D18, D77, D111, D122)
Дата: 2026-10-28

## Контекст
Пользователь: «иногда у меня появляются сомнения на счет выбранного стека для программы».
Разобрали: файл SQLite на компанию (D18) — бэкап копированием, снимок без записи (D80), SQL
уже общий с PostgreSQL (D77); Python — для правил учёта, деньги целые (D3), агрегация в SQL;
написано ~100 000 строк, 58 миграций, 178 решений — переписывать дороже любой выгоды.
Слабое место — Qt: дизайн уровня Things доводится руками; установка (`uv`, `pythonw`) для
продажи (D111) потребует инсталлятора. Пользователь: «следуем вашему совету».

## Решение
- Стек остаётся: Python, файл SQLite на компанию, PySide6. Вопрос о замене стека закрыт;
  открывается снова только отдельным решением пользователя.
- Ядро (`domain`, `application`, `reporting`, `api`, `assistant`) не зависит от Qt: интерфейс
  можно заменить или дополнить (веб поверх `api`), не трогая учёт. Это и есть защита от
  сомнений — не переписывание.
- Производительность — в SQL, не в циклах Python (`scripts/benchmark.py`); установка для
  продажи — отдельная задача, не повод менять стек.
