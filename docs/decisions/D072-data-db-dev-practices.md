# D72 — Лучшие практики данных, базы и разработки — те же постоянные правила
Статус: принято
Дата: 2026-10-21

## Контекст
—

## Решение
**Лучшие практики данных, базы и разработки — те же постоянные правила** (сессия 21, пользователь: «всё должно соответствовать лучшим практикам архитектуры данных, разработки, структуры базы; постоянно проверять»; дополняет D71). `docs/MODULARITY.md` переименован в `docs/ENGINEERING.md`: разделы «Архитектура данных» (один источник правды, производное пересчитывается, история не теряется, импорт без дублей, секреты не в файле компании), «Структура базы» (`company_id NOT NULL`, составные FK, индекс на каждую ссылку, типы без `REAL`, `CHECK`, осознанный `ON DELETE`, миграции неизменны, имена), «Разработка» (ветка на задачу, CI, тест прежде исправления, транзакция на сценарий, типизированные входы, ошибки домена, сложность ≤ 12). Схему проверяет `tests/test_database.py`: номера миграций подряд, хэши написанных миграций, `company_id`, составные FK, типы, индексы ссылок (полностью — для новых таблиц, «строка → документ» — для всех), целостность демо-компании. Нынешние отклонения — исключения в тесте и пункты 4–5 долга.

## Последствия
