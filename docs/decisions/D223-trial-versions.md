# D223 — Пробные версии: релиз сначала приходит только тому, кто их проверяет
Статус: принято
Дата: 2026-11-25

## Контекст
Пользователь: «программа ещё в разработке, я часто буду что-то добавлять или улучшать. Боюсь,
что обновления могут что-то сломать». По D191 каждый релиз за час доходил до работника с
живой базой; между правкой и его данными не было ступени проверки, а после обновления схемы
прежняя программа файл уже не откроет (D148).

## Решение
- **Релиз выходит пробной версией** (GitHub «pre-release», `release.yml`). Программы спрашивают
  `/releases/latest` — GitHub пробные там не показывает, поэтому работнику (и всем
  установленным раньше версиям) ничего не предлагается.
- **«Пробные версии программы»** — галочка в меню компании, настройка этого компьютера
  (`updates/trial`). С ней программа спрашивает все релизы и берёт самый новый по номеру;
  строка — «Вышла пробная версия … — обновить».
- **Порядок:** `release.py <версия> --push` → пробная версия у владельца → открыть ею копию
  живой базы работника (из второй папки копий) → `release.py <версия> --publish`
  (`gh release edit --prerelease=false --latest`) — версия для всех, работнику её предложат
  в течение часа.
- Уточняет D189 (выпуск) и D191 («исправление доходит сразу» — теперь после `--publish`).

## Последствия

`release.yml`; тесты — `tests/test_updates.py`.
