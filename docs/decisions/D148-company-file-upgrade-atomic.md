# D148 — Обновление файла компании — всё или ничего; старая программа не трогает новый файл; каждая схема — тест на настоящем файле
Статус: принято
Дата: 2026-10-26

## Контекст
—

## Решение
**Обновление файла компании — всё или ничего; старая программа не трогает новый файл; каждая схема — тест на настоящем файле** (ветка `claude/schema-safety`; пользователь: «пользователи пользуются действующей версией… обновления не поломают структуру?», «очень серьёзно разработать этот механизм и защиту»). (1) Ждущие миграции — одна транзакция (`db.migrate`, операторы — по `sqlite3.complete_statement`): сбой оставляет файл прежней версии. (2) Схема файла новее программы — `NewerFileError` до любой записи (окно, просмотр, API, AI). (3) Сбой обновления — `UpgradeError` с путём копии, а не вылет окна. (4) Последняя копия каждой из 3 прежних схем живёт сверх 30 обычных. (5) `tests/fixtures/upgrade/schema_NNNN.gl.xz` — демо-год той схемы от её программы (49 — `d2a0c67`, раньше история сжата) с её ОСВ: после обновления цифры те же, модули строят те же проводки; новая схема добавляет свой файл. Версии без (2) новый файл откроют — обновить всех.
