# Состояние проекта — 2026-10-20 (двенадцатая сессия)

Читать в начале новой сессии вместе с `CLAUDE.md` и `docs/DECISIONS.md`.

## Что это
Настольная бухгалтерская программа (главная книга) для бухгалтеров-консультантов в Азербайджане: проводки Дт/Кт с субконто как в 1С 7.7, но простая, быстрая и красивая (ориентир дизайна — Things от Cultured Code). Цель владельца продукта: **взять простотой — всё быстро и просто, но легко настраивается.**

**Главная цель (уточнено в сессии 5, D30):** не продажа, а очень удобный и гибкий
инструмент для собственной работы владельца. Сценарий: один бухгалтер на одном рабочем
месте ведёт несколько независимых фирм, каждая в отдельном переносимом файле; локально,
offline-first. **Модульность:** ядро (GL) самодостаточно, модули (склад, позже ОС,
e-qaimə) — по желанию; у пользователя есть отдельное расширение etax-ext (e-qaimə) и
программа учёта ОС, которые позже можно подключить через импорт документов.
**Дизайн** — главный приоритет: Things и сайт Cultured Code, craft.do; «отполировать до блеска».

## Как запустить
- Программа: `uv run modern-gl` (компании — файлы `*.gl` в «Документы\Modern GL»); `uv run modern-gl --demo` — с демо-компанией.
- Если программа открыта, `uv run` не может обновить exe → закрыть программу или `uv run --no-sync …`.
- Тесты: `uv run pytest -q` (404 теста, ~1,5 мин). Линтер: `uv run ruff check . && uv run ruff format --check .`. Типы: `uv run pyright` (0 ошибок).
- Скриншоты для проверки дизайна: `uv run python scripts/screenshots.py <папка> az` — смотреть после любых изменений UI.
- У пользователя остался старый `D:\GL AZE\demo.db` (несколько тестовых компаний в одном файле) — подключается через «Fayldan əlavə et…», программа разложит его по файлам.

## Что готово
**Ядро учёта** (`application/ledger/`, `reporting/reports.py`)
- Документ = 1..N проводок «Дт/Кт/сумма» + до 3 субконто на сторону; деньги — целые копейки.
- Черновик → проведение; исправление: красное сторно, либо (в открытом периоде) «отменить проведение» / удалить с полной копией в журнале действий; закрытие периода (`set_closed_through`, **UI пока нет**).
- Номера документов не повторяются; журнал действий только на добавление; триггеры БД защищают проведённое.
- Слои/книги: общий, МСФО-корректировки, налоговые корректировки (книга = набор слоёв).
- Отчёты: ОСВ (группы, развёрнутое сальдо для счетов «с обеих сторон», флаги «сальдо не на своей стороне», разбивка по 1-му субконто), ОСВ по субконто, карточка счёта, анализ счёта.
- **Начальные остатки** (сессия 10, D39–D40, миграция 0017): отдельный раздел в боковой панели (Ctrl+9); одна таблица как ОСВ — счёт, субконто, «Дебет» или «Кредит», валюта, E-qaimə; вставка из Excel по заголовкам. Итоги могут не совпадать: разница остаётся на счёте 00 «Ввод начальных остатков» (виден в плане счетов и ОСВ), кнопка «Разницу — на счёт…» закрывает её видимой строкой. Документ GL датирован днём раньше даты остатков, поэтому в ОСВ это «Сальдо нач.». Код — группа `Ledger` `ledger/opening.py` (`opening_account`, `save_opening_balances`), чтение — `queries.opening_document`; на 00 проводит только этот документ (сторно запрещено — документ правится и перепроводится). Таблица — `OpeningPostingsModel` поверх `PostingsModel` (лишняя колонка «Кредит», порядок колонок задаёт `column_order()`).

**Шаблоны операций** (раздел «Şablonlar», Ctrl+5; миграция 0006, `domain/formula.py`, `desktop/templates_page.py`)
- Шаблон = строки Дт/Кт (+ субконто по желанию) и формула суммы: `S` — сумма операции, `L1, L2…` — суммы строк, числа, + − * / ( ). Пример: «Satış ƏDV ilə»: 62/46 = S, 46/68.2 = S*18/118. Округление только итога строки, до копеек, половина — от нуля.
- Enter на шаблоне → новый документ с полем «Сумма операции»; строки с формулой пересчитываются при вводе, сумма, введённая вручную, больше не меняется.
- «Şablon et» в документе: сумма как у первой строки → `S`, остальные — числом; сразу открывается редактор шаблона с предпросмотром «при сумме 1 000.00».
- В новой компании 15 готовых шаблонов по плану «classic» (`templates/entries_classic_{az,ru}.csv`): продажа/покупка с ƏDV, зачёт ƏDV, оплаты, зарплата, подотчёт, банк, финрезультат. Ставки зарплатных удержаний не заложены (там S, сумма вручную).

**Склад и landed cost** (раздел «Anbar / Склад», Ctrl+6; миграция 0007,
`application/inventory.py`, `reporting/inventory.py`)
- Товары, единицы измерения и склады используют общие с GL субконто.
- Начальные остатки, поступление, списание и перемещение; средневзвешенная
  себестоимость, запрет отрицательного остатка и автоматические проводки.
- Дополнительные расходы распределяются по стоимости, количеству или вручную.
  Поздний landed cost делится между стоимостью остатка и расходным счётом уже
  списанного товара; виды расходов хранятся в отдельном справочнике.
- Складской регистр и GL проводятся одной транзакцией; связанную проводку нельзя
  отдельно удалить или распровести через журнал.
- Складские документы имеют многострочную карточку, черновики, проведение и отмену
  проведения в открытом периоде; связанные проводки открываются из карточки.
- Безопасное ограничение первой версии: складские документы проводятся только по
  порядку дат (черновик можно сохранить любой датой — проверка при проведении).
- Черновик складского документа сохраняется недописанным: обязателен только товар,
  остальное (склад, количество, сумма, счёт, субконто) проверяется при проведении.
- В таблице складского документа ячейки-списки работают как в проводках: поиск,
  Enter **и Tab** берут выбранное; если введённого имени нет — предлагается добавить
  (контрагент, договор и любое субконто, склад; товар — через окно «Новый товар»).
- В новой строке подставляется только счёт (60 / 46); субконто остаются пустыми,
  чтобы документ не провёлся на случайного контрагента.
- Подробная модель и этапы: [`docs/INVENTORY.md`](INVENTORY.md).

**Мультивалютность** (сессия 3; миграция 0008, `domain/currency.py`, `application/currencies.py`,
`infrastructure/cbar.py`, `desktop/currencies_page.py`; решение D28)
- Счёт с признаком «Учёт в валюте» (галочка в окне счёта; в шаблонах — 52). Каждая проводка
  по нему несёт валюту и сумму в валюте; одна валюта на проводку.
- Ввод: колонки «Валюта / В валюте / Курс» появляются, только когда в документе есть строка
  с валютным счётом. Курс подставляется на дату документа (меняется при смене даты, пока его не
  ввели вручную); сумма в манатах = сумма в валюте × курс, её можно поправить.
- Элементу справочника (банковский счёт, договор, контрагент) можно задать валюту
  (контекстное меню «Валюта…» в «Справочниках»): строка берёт её сама, при проведении
  проверяется совпадение.
- Раздел «Валюты» (Ctrl+7): список валют с последним курсом, история курсов, ввод вручную
  (Ins / двойной щелчок / Del), «Курсы ЦБА…» — загрузка с cbar.az за день или период (до 92 дней),
  «Переоценка…» — документ курсовых разниц на дату (по умолчанию на 80).
- Отчёты: в карточке валютного счёта — валюта и суммы в ней, остаток в валюте в итоге; в ОСВ
  галочка «В валюте» — строки по валютам под валютными счетами.
- **Не проверено вживую:** загрузка с cbar.az (из облачной среды сайт недоступен) — парсер
  написан по формату XML ЦБА и проверен на тестовом примере. Проверить у пользователя:
  «Valyutalar» → «AMB məzənnələri…».
- Не сделано: валюта в шаблонах операций и складских документах; конвертация валют одной
  проводкой (через транзитный счёт); автоматическая загрузка курсов при запуске.

**Сессия 5: договоры контрагентов, 60/62 в манатах и валюте, курс ЦБА из документа,
подсказки в быстрой строке** (миграция 0009; D28, D29)
- Валютный учёт счёта — три режима (окно счёта, поле «Валюта»): только манаты / манаты и
  валюта / только валюта. В шаблонах 60 и 62 (1c77: 60.1, 60.2, 62.1, 62.2) — «манаты и
  валюта»; миграция включила это на 60/62 существующих компаний, если на них нет проводок
  с чужой валютой. Строка на 60 с местным контрагентом — без колонок валюты; в «Сумме»
  можно написать `500 USD` / `EUR 500` — строка становится валютной (курс даты, манаты по
  курсу). Режим счёта с проводками меняется, если старые проводки ему подходят.
- Договоры принадлежат контрагентам (`subconto_kinds.owner_kind_id`, `subconto_values.owner_id`):
  в форме, складском документе, быстрой строке, вставке и импорте предлагаются договоры
  выбранного контрагента и общие; новый договор из строки получает её контрагента; при
  смене контрагента чужой договор убирается; при проведении — проверка. У двух
  контрагентов может быть по своему «Фактура 15». В «Справочниках»: колонка контрагента,
  окно договора с выбором контрагента, в меню контрагента «Добавить в «Договоры»…».
  Миграция: договор, использованный ровно с одним контрагентом, получил его как владельца.
- Курс ЦБА из документа: если на дату документа своего курса нет (взят старый или нет
  вообще), под таблицей плашка «На 10.03.2026 курс не загружен… — Загрузить курс ЦБА»;
  загрузка с cbar.az на дату документа, строки пересчитываются (`Session.fetch_rates`).
- Быстрая строка подсказывает по ходу ввода (`quick_entry.suggest`, без Qt): счета, после
  «26 » — его статьи затрат (недавние первыми), после «60 Бета, » — договоры Беты, после
  суммы «us» → USD, после «#» — шаблоны. Enter/Tab берёт пункт и дописывает « / » или «, ».
  Названия с числами («Фактура 15 400») разбираются верно.
  Если элемента нет (новая база: «51 » — банков ещё нет) — в списке пункт «+ Добавить «X» в
  «справочник»» (при пустом справочнике — «+ Новый элемент…»); Enter вставляет `+X`, элемент
  создаётся при проведении. Переходить в «Справочники» не нужно. Ошибка разбора во время набора —
  серой подсказкой, красная — только при Enter.
- Выпадающие списки больше не показывают полосу прокрутки при 2–3 пунктах (`fit_popup`).

**Сессия 6: правка проведённого как в 1С** (ветка `claude/edit-posted-inventory-vat`; D32)
- Проведённый документ GL в открытом периоде открывается редактируемым; «Провести»/Ctrl+S —

**Сессия 7: склад, этап 2 — НДС в поступлении** (D34; миграция 0010)
- В шапке поступления — ставка НДС (18% / Без НДС); колонка «НДС» после «Суммы»: считается
  по ставке, пока её не ввели вручную (очистить ячейку — снова по ставке); при «Без НДС»
  колонка скрыта. Внизу — «НДС» и «Итого» с НДС. Вставка из Excel понимает колонку «НДС/ƏDV».

**Вставка из Excel** (сессия 3; `desktop/postings.py`: `PostingsModel.paste/copy_text`)

**Быстрый ввод одной строкой** (сессия 3; `application/quick_entry.py` — разбор без Qt,
`desktop/quick_entry_bar.py` — строка над журналом; Ctrl+L из любого места)
- `[дата] Дт [субконто, субконто] / Кт [субконто…] сумма [валюта] [содержание]`, например
  `26 аренда / 60 альфа, договор 400 Аренда за март`; `05.03` в начале — дата (иначе рабочая);
  проводки одного документа — через «;». Сумма пишется без пробелов (1234,50).
- `+Имя` — новый элемент справочника (создаётся при проведении, в той же транзакции).
- `#шаблон сумма [субконто, …]` — шаблон операции: S = сумма, части после суммы заполняют
  пустые субконто шаблона (один справочник — везде, где пуст), остальное — содержание.
- Валютная строка: число — в валюте (из «1000 USD» или из валюты банковского счёта/договора),
  манаты по курсу даты.
- Под строкой — как она понята (счета, субконто, суммы, что не заполнено, что будет добавлено)
  или ошибка с подсказкой. Enter — провести, Shift+Enter — черновик, Ctrl+Enter — открыть в
  форме (дописать), ↑/↓ — прошлые строки, Esc — очистить.
- Журнал: Enter/Del/F9 теперь работают только в списке (не мешают строке и поиску).

## Архитектурный аудит — отложенные технические работы

Текущее состояние: крепкий MVP с чистым разделением слоёв, целочисленными деньгами,
атомарными транзакциями, защитными ограничениями SQLite и хорошим набором тестов.
До использования на реальных клиентских данных закрыть следующие направления:

1. **Надёжность данных (до пилота):** автоматические резервные копии через SQLite Backup
   API, хранение последних 30 копий, ручная команда «Сохранить копию», восстановление из
   копии с обязательным тестом восстановления, `quick_check` / периодический
   `integrity_check`, резервная копия перед миграцией схемы.
2. **Безопасный жизненный цикл файлов:** создавать и импортировать компанию сначала во
   временный файл и атомарно переименовывать только после успеха; удалять неполный файл
   при ошибке. Перед разделением старого общего файла сначала обновлять его копию до
   текущей схемы: сейчас `_extract()` предполагает наличие таблиц новых миграций и может
   не обработать файл старше `0006`. Добавить тест импорта каждой поддерживаемой версии.
3. **Масштабирование интерфейса:** журнал сейчас загружает все документы; нужны фильтры и
   постраничная/оконная загрузка. Тяжёлые отчёты и импорт выполнять вне UI-потока с
   индикатором, отменой и безопасными отдельными соединениями SQLite.
4. **Измеряемая производительность:** генератор 10k/100k/1M проводок, замеры p50/p95,
   планы SQL-запросов, размер базы и памяти; оптимизировать и добавлять агрегаты только по
   результатам профилирования.
5. **Поставка и контроль качества:** Windows CI (сейчас CI только на Ubuntu: тесты, Ruff, pyright; нужны Windows и сборка), установщик,
   проверка обновления на копии пользовательской базы, понятные сообщения о сбоях без
   попадания клиентских данных в логи.
6. **Бухгалтерская приёмка:** независимая сверка ОСВ, карточек, сторно, слоёв и закрытия
   периода на обезличенном реальном примере. До успешной сверки и проверки
   backup/restore не считать программу готовой для клиентского учёта.

**Стек:** Python + PySide6 + SQLite остаётся основным для локальной однопользовательской
версии и соответствует коммерческому сценарию «один консультант — много фирм».
Пересматривать его нужно не из-за размера кода, а при переходе к одновременной работе
нескольких пользователей с одной фирмой, серверной авторизации/API или очень тяжёлым
фоновым расчётам. В таком случае доменную модель можно сохранить, UI оставить на PySide6
или заменить веб-клиентом, а хранение перенести на сервер/PostgreSQL.

## Известные особенности
- Минимальную ширину окна задаёт только открытая страница (`MainWindow._size_by_current_page`); раньше после открытия ОСВ окно не сжималось уже 1800 px, и на ноутбуке правые колонки уходили за экран. Заголовки страниц (`ElidedLabel`) обрезаются с «…». ОСВ всё ещё требует ~1330 px (четыре флажка в шапке), «Soraqçalar» ~1270 — кандидаты на перекомпоновку.
- `SPEC.md` и `ARCHITECTURE.md` — исходные документы v0.1, местами устарели; приоритет у `docs/DECISIONS.md` (D1–D31).
- `QTest.keyClicks` в PySide под Windows падает на не-латинских буквах → в тестах `type_text()`.
- Модальные диалоги в тестах подменяются (`no_modal_dialogs`), иначе тест виснет.
- Скриншоты в режиме offscreen: экран 800 px, поэтому выпадающие списки на снимках сдвинуты влево — в реальной программе всё на месте.
- Поведение выпадающих списков с клавиатуры проверять и в реальном окне (`QT_QPA_PLATFORM=windows`): в offscreen порядок событий может отличаться.
